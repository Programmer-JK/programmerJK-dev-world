## 1. 양자화 기본 개념

### 파인튜닝 모델의 양자화 구조 (QLoRA)

```
┌─────────────────────────┐
│   LoRA 어댑터 (bf16)     │  ← 학습되는 부분 (수 MB~수백 MB)
├─────────────────────────┤
│  베이스 모델 (양자화됨)    │  ← 동결(frozen), 양자화 방식에 따라 크기 다름
└─────────────────────────┘
```

- 베이스 모델 가중치: 양자화된 상태로 고정 (학습 안 됨)
- 어댑터 가중치: bf16 정밀도로 학습됨
- 추론 시: 양자화된 베이스 + bf16 어댑터가 합쳐져서 결과 생성

### 정밀도별 크기 비교

| 정밀도 | 모델 크기 비율 | 설명 |
|--------|:---:|------|
| FP32 | 100% | 학습 원본, 추론에는 안 씀 |
| BF16 | 50% | FP16과 크기 동일, 범위가 더 넓음 (학습에 유리) |
| FP16 | 50% | 일반적인 추론 기준점 |
| FP8 | 25% | Ada/Hopper GPU 네이티브 지원 |
| INT8 | 25% | 정수 양자화, 범용적 |
| FP4 / NF4 | 12.5% | bitsandbytes QLoRA에서 사용 |
| INT4 | 12.5% | GPTQ, AWQ 등 |

## 2. 양자화 방식(알고리즘) 종류

### vLLM에서 지원하는 방식

| 방식 | 비트 | vLLM 지원 | 특징 |
|------|:---:|:---:|------|
| FP16 / BF16 | 16 | O | 품질 기준점 |
| FP8 | 8 | O (L4 네이티브) | 품질↑ 속도↑ |
| bitsandbytes INT8 | 8 | O | 정수 양자화 |
| GPTQ | 4/8 | O | 캘리브레이션 기반, 높은 품질 |
| AWQ | 4 | O (Marlin 커널) | 추론 속도 최적화, vLLM 최적 |
| bitsandbytes NF4 | 4 | O | 현재 학습에서 사용 중 |

### vLLM에서 지원하지 않는 방식

| 방식 | 비트 | 특징 |
|------|:---:|------|
| EXL2 | 2~8 | ExLlamaV2 전용, 레이어별 혼합 비트 |
| GGUF | 2~8 | llama.cpp / Ollama 전용, CPU 추론 가능 |
| HQQ | 2~4 | 캘리브레이션 불필요 |
| QuIP# | 2/4 | 2-bit에서도 높은 품질 |
| AQLM | 2~4 | 코드북 기반 극한 압축 |

### 4bit 방식별 차이

같은 4bit라도 양자화 알고리즘에 따라 품질/속도가 다름:

| 방식 | 특징 | 캘리브레이션 | vLLM 추론 속도 |
|------|------|:---:|:---:|
| NF4 (bitsandbytes) | 현재 학습에서 사용, 설치 간단 | 불필요 | 보통 |
| GPTQ | 캘리브레이션 기반, 높은 품질 | 필요 (128+ 샘플) | 빠름 |
| AWQ | 중요 가중치 보호, Marlin 커널 | 자동 | 매우 빠름 |

## 3. 학습-서빙 양자화 불일치 문제

### 현재 상태

```
학습: NF4 4-bit 양자화 베이스 위에서 LoRA 학습
서빙: FP8 양자화 베이스 위에 동일 LoRA 어댑터 로드
```

어댑터가 NF4 기준으로 최적화되었는데, FP8 베이스 위에 얹으면 미세한 불일치 발생.

### 불일치 영향 정도

| 상황 | 영향 |
|------|------|
| NF4 학습 → NF4 서빙 | 완벽히 일치 |
| NF4 학습 → FP8 서빙 **(현재)** | 미미함 (FP8이 FP16에 더 가까워 베이스 품질은 오히려 좋아짐) |
| NF4 학습 → INT8 서빙 | 미미함 |
| NF4 학습 → FP16 서빙 | 미미함 |
| NF4 학습 → 다른 4bit (GPTQ/AWQ) 서빙 | **차이 클 수 있음** (같은 4bit인데 양자화 오차 패턴이 다름) |

> FP8/INT8/FP16은 NF4보다 정밀도가 높아서 원본(FP16)에 가깝고, 어댑터가 학습한 방향성은 대체로 유효함.
> 같은 4bit끼리 방식이 다르면 오차 패턴 자체가 달라서 문제가 될 수 있음.

## 4. AWQ가 vLLM에서 추천되는 이유

vLLM에서 AWQ 4bit 로드 시 **Marlin 커널**이 자동 활성화됨:

- FP16 대비 **3~4배 빠른 추론 속도**
- 4bit 양자화 중 vLLM에서 가장 최적화된 경로
- GPTQ도 Marlin 지원하지만 AWQ가 더 안정적

```bash
# vLLM에서 AWQ 모델 서빙 예시
vllm serve /path/to/Qwen3-32B_awq_4bit \
    --quantization awq_marlin \
    --tensor-parallel-size 2
```

| Q3_K_M | ~3.3bit | 보통 | ~15GB |

| Q6_K | ~6.5bit | 거의 FP16 | ~26GB |
