## 한 일

- **양자화**: FP8, INT8, AWQ, GPTQ, GGUF를 비교 테스트했다. merge 후 재양자화, 캘리브레이션 데이터 준비, llama.cpp 변환까지 직접 돌렸다. 개념은 [LLM 양자화 방식 정리](/posts/llm-quantization-methods)에 남겼다.
- **모델 대체안**: 0.6B부터 30B MoE까지 여러 크기의 모델을 같은 테스트 셋으로 평가했다.
- **플랫폼**: 허용 리소스 화이트리스트, 파일 스토어, DB 뷰어, 채팅, 문의 기능을 만들었다. 기능마다 "왜 하는가 → 만들 것 → 수정 파일 → 리스크 → 확인 방법" 순서로 계획서를 먼저 썼다.
- **조사**: OpenRouter 같은 모델 라우팅 서비스를 장단점 중심으로 정리해 팀에 공유했다.
- **정리**: 환경 설정 문서를 정리하고, 그동안 참여한 프로젝트의 기여 내역을 돌아봤다.

## 배운 것

- 양자화는 모델 크기만이 아니라 GPU 아키텍처와 커널 지원에 달려 있다. 같은 방식도 하드웨어에 따라 더 느려질 수 있다.
- 학습할 때의 양자화와 서빙할 때의 양자화가 다르면 미세한 불일치가 생긴다. 실무에서는 큰 문제가 아니어도 알고는 있어야 한다.
- 계획서를 먼저 쓰면 구현이 빨라진다. 1년 반 동안 업무일지를 쓰면서 가장 크게 바뀐 습관이다.
