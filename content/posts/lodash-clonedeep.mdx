## cloneDeep 동작 방식

`_.cloneDeep()`은 lodash 라이브러리의 함수로, 객체의 깊은 복사(deep copy)를 수행합니다:

1. **재귀적 복사**: 객체의 모든 중첩 구조(객체, 배열 등)를 재귀적으로 탐색하여 복사합니다.
2. **새로운 메모리 할당**: 원본 객체와 완전히 별개의 메모리 공간에 새로운 객체를 생성합니다.
3. **참조 관계 보존**: 복잡한 참조 관계나 순환 참조도 올바르게 처리합니다.
4. **프로토타입 체인 복사**: 원본 객체의 프로토타입 체인도 복사됩니다.
5. **특수 객체 처리**: Date, RegExp, Map, Set 등과 같은 특수 객체 타입도 적절히 복사합니다.

## cloneDeep 사용이 적합한 상황

1. **원본 객체 보존이 필수적인 경우**:
    
    - 원본 데이터를 변경하지 않고 복사본을 수정해야 할 때
    - 상태 관리 시스템에서 이전 상태를 유지하며 새 상태를 생성할 때
2. **중첩된 데이터 구조를 완전히 복제해야 하는 경우**:
    
    - 복잡한 구성 객체를 복제하여 일부만 수정해야 할 때
    - 깊은 수준의 객체 속성을 안전하게 수정해야 할 때
3. **객체 스냅샷이 필요한 경우**:
    
    - 특정 시점의 데이터 상태를 저장해야 할 때
    - 작업 취소/복구(undo/redo) 기능 구현 시

## cloneDeep 사용을 피해야 하는 상황

1. **대용량 데이터 처리 시**:
    
    - 큰 객체나 데이터 집합을 다룰 때는 메모리 사용량이 급증할 수 있음
    - 예시: 대량의 레코드가 포함된 데이터셋, 큰 이미지 데이터 등
2. **성능이 중요한 경우**:
    
    - 깊은 복사는 계산 비용이 높은 작업임
    - 실시간 처리나 반복적인 작업에서는 성능 저하가 발생할 수 있음
3. **얕은 복사로 충분한 경우**:
    
    - 단순한 객체 구조나 1단계 깊이의 복사만 필요할 때는 `Object.assign()`이나 전개 연산자(`...`)가 더 효율적
4. **특정 속성만 필요한 경우**:
    
    - 전체 객체가 아닌 일부 속성만 필요한 경우에는 필요한 속성만 명시적으로 복사하는 것이 효율적

## 대안 및 최적화 방법

1. **선택적 복사**: 필요한 속성만 명시적으로 복사
    
    ```javascript
    const copy = {
      id: original.id,
      name: original.name,
      // 필요한 속성만 나열
    };
    ```
    
2. **중첩 객체만 깊은 복사**: 특정 중첩 객체만 깊은 복사 적용
    
    ```javascript
    const copy = {
      ...original,
      options: _.cloneDeep(original.options)
    };
    ```
    
3. **구조 설계 개선**: 데이터 구조를 재설계하여 깊은 복사의 필요성 자체를 줄이기
    
    - 불변 데이터 패턴 적용
    - 중앙 저장소에서 데이터 관리하고 참조만 사용

cloneDeep은 강력하지만 비용이 높은 연산이므로, 꼭 필요한 상황에서만 선택적으로 사용하는 것이 좋습니다.
