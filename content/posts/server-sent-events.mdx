## 1. 개요

**Server-Sent Events (SSE)**는 HTTP 기반의 스트리밍 기술로,
서버가 클라이언트(브라우저)에게 **지속적으로 데이터를 푸시(push)**할 수 있게 해준다.

* 프로토콜: HTTP
* 방향성: **서버 → 클라이언트 (단방향)**
* 연결: **지속 연결 (persistent connection)**

---

## 2. 동작 원리

SSE는 HTTP 요청-응답 구조를 유지하면서도,
**응답을 종료하지 않고 계속 데이터를 전송**하는 방식으로 동작한다.

### 흐름

1. 클라이언트가 서버에 요청
2. 서버는 `Content-Type: text/event-stream`으로 응답 시작
3. 서버는 연결을 끊지 않고 데이터를 지속적으로 전송
4. 클라이언트는 이벤트 단위로 데이터를 수신

---

## 3. HTTP 헤더

SSE를 사용하기 위해 서버는 다음 헤더를 설정해야 한다:

```http
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

### 설명

| 헤더            | 설명           |
| ------------- | ------------ |
| Content-Type  | SSE 스트림임을 명시 |
| Cache-Control | 캐싱 방지        |
| Connection    | 연결 유지        |

---

## 4. 데이터 포맷

SSE는 특정한 텍스트 기반 포맷을 사용한다.

### 기본 구조

```text
data: 메시지 내용

```

> **빈 줄(\n\n)**은 하나의 이벤트 종료를 의미

---

### 다양한 필드

```text
event: message
data: hello

id: 123
data: world

retry: 5000
data: reconnect test

```

| 필드    | 설명                |
| ----- | ----------------- |
| data  | 실제 데이터            |
| event | 이벤트 이름            |
| id    | 이벤트 ID (재연결 시 사용) |
| retry | 재연결 시간(ms)        |

---

## 5. 클라이언트 구현

브라우저에서는 `EventSource` API를 사용한다.

```javascript
const eventSource = new EventSource('/api/stream');

eventSource.onmessage = (event) => {
  console.log(event.data);
};

eventSource.onerror = (error) => {
  console.error('SSE error:', error);
};
```

### 특징

* 자동 재연결 지원
* 이벤트 기반 수신
* 간단한 API

---

## 6. 서버 구현

### Node.js (Express) 예시

```javascript
app.get('/api/stream', (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  const interval = setInterval(() => {
    res.write(`data: ${new Date().toISOString()}\n\n`);
  }, 1000);

  req.on('close', () => {
    clearInterval(interval);
  });
});
```

### 핵심 포인트

* `res.write()`로 데이터 전송
* `res.end()` 호출하지 않음
* 연결 종료 감지 (`req.on('close')`)

---

## 7. 재연결 메커니즘

SSE는 연결이 끊어질 경우 자동으로 재연결을 시도한다.

### 동작 방식

* 브라우저가 자동 재요청 수행
* 마지막 이벤트 ID(`Last-Event-ID`) 전달 가능

```http
Last-Event-ID: 123
```

---

## 8. 장점

### ✔️ 구현 간단

* HTTP 기반
* 별도 프로토콜 필요 없음

### ✔️ 자동 재연결

* 클라이언트 로직 단순화

### ✔️ 스트리밍에 적합

* LLM 응답, 로그 스트리밍 등

---

## 9. 단점

### ❌ 단방향 통신

* 클라이언트 → 서버는 별도 요청 필요

### ❌ 바이너리 데이터 제한

* 텍스트 기반만 지원

### ❌ 연결 수 제한 (브라우저)

* 동일 도메인당 연결 수 제한 존재

---

## 10. SSE vs WebSocket

| 항목     | SSE  | WebSocket    |
| ------ | ---- | ------------ |
| 프로토콜   | HTTP | WS (Upgrade) |
| 방향성    | 단방향  | 양방향          |
| 구현 난이도 | 낮음   | 높음           |
| 재연결    | 자동   | 직접 구현        |
| 사용 사례  | 스트리밍 | 실시간 채팅       |

---

## 11. 사용 사례

### ✔️ LLM 응답 스트리밍

* 토큰 단위 응답 전송

### ✔️ 실시간 알림

* 서버 이벤트 전달

### ✔️ 로그 스트리밍

* 서버 상태 모니터링

---

## 12. Best Practices

### 1. Keep-alive 유지

```javascript
res.write(': keep-alive\n\n');
```

### 2. 타임아웃 방지

* 주기적으로 heartbeat 전송

### 3. 연결 정리

```javascript
req.on('close', cleanup);
```

### 4. 프록시 설정 주의

* Nginx 등에서 buffering 비활성화 필요

---

## 13. 결론

SSE는 다음과 같은 상황에서 최적의 선택이다:

* 서버 → 클라이언트 **단방향 스트리밍**
* 구현 단순성이 중요한 경우
* LLM 응답, 실시간 로그 등

---

## 🔥 핵심 요약

> SSE는 HTTP 연결을 유지한 채,
> 서버가 클라이언트에게 이벤트 스트림을 지속적으로 전달하는 기술이다.
