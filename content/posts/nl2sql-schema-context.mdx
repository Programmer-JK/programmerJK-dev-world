NL2SQL의 정확도는 모델보다 프롬프트에 들어가는 스키마에서 먼저 갈린다. 모든 테이블을 넣으면 토큰이 넘치고, 너무 적게 넣으면 조인을 틀린다.

## 스키마도 검색 대상이다

테이블 설명과 컬럼 설명을 문서처럼 쪼개 벡터와 BM25로 함께 검색했다. 결국 RAG 문제였다.

## 프롬프트에 남긴 것

- 질문과 관련된 테이블 상위 몇 개
- 조인 키와 자주 쓰는 필터 예시
- 금지 규칙: DELETE, UPDATE 생성 금지
