지도 라이브러리를 바꾸면서 지점 좌표를 위경도로 넘겨야 했다. 그런데 DB의 좌표(예: `507006, 1045259`)는 위경도가 아니라 **카카오 내부 좌표(WCONGNAMUL)**였다.

## 좌표계 정리

| 용어 | 의미 |
|---|---|
| **WGS84** | GPS의 위도·경도(도 단위). 지도 라이브러리 대부분이 받는 형식 |
| **TM** (횡단 메르카토르) | 타원체 위 좌표를 평면 미터 좌표로 투영. 원점에서 멀수록 왜곡이 커서 지역별 원점을 둔다 |
| **가산값** | 좌표가 음수가 되지 않게 더하는 값. 여기선 동쪽 200,000 · 북쪽 500,000 |
| **WCONGNAMUL** | 카카오 내부 좌표. TM에 2.5를 곱한 값이라 2.5로 나누면 TM |
| **GRS80** | 타원체 (장반경 6,378,137m, 편평률 1/298.257222101). WGS84와 실무상 같다 |

## TM 역변환 순서

1. 평면 좌표에서 가산값을 빼 원점 기준 거리로 만든다.
2. 북쪽 거리로 자오선 길이를 구하고, 그에 해당하는 "발 위도(footpoint latitude)"를 급수로 계산한다.
3. 발 위도에서의 곡률 반경과 동쪽 거리 비율로 위도·경도 보정 급수를 적용한다.
4. 라디안을 도로 바꾼다.

## 함수

```sql
CREATE OR REPLACE FUNCTION FN_WCONG_TO_WGS84 (
  p_wx IN NUMBER, p_wy IN NUMBER, p_type IN VARCHAR2   -- 'LAT' 또는 'LNG'
) RETURN NUMBER
DETERMINISTIC
IS
  PI CONSTANT NUMBER := ACOS(-1);
  a  CONSTANT NUMBER := 6378137;
  f  CONSTANT NUMBER := 1 / 298.257222101;
  k0 CONSTANT NUMBER := 1;
  FE CONSTANT NUMBER := 200000;
  FN CONSTANT NUMBER := 500000;
  e2 NUMBER; e4 NUMBER; e6 NUMBER; ep2 NUMBER; e1 NUMBER;
  lat0 NUMBER; lon0 NUMBER; x NUMBER; y NUMBER;
  m0 NUMBER; m NUMBER; mu NUMBER; p1 NUMBER;
  s NUMBER; c NUMBER; t NUMBER;
  C1 NUMBER; T1 NUMBER; N1 NUMBER; R1 NUMBER; D NUMBER;
  v_lat NUMBER; v_lon NUMBER;
BEGIN
  IF p_wx IS NULL OR p_wy IS NULL THEN RETURN NULL; END IF;

  x := p_wx / 2.5;  y := p_wy / 2.5;                 -- WCONGNAMUL → TM
  e2 := 2*f - f*f;  e4 := e2*e2;  e6 := e4*e2;  ep2 := e2 / (1 - e2);
  lat0 := 38 * PI / 180;  lon0 := 127 * PI / 180;    -- 원점 38°N, 127°E

  m0 := a * ( (1 - e2/4 - 3*e4/64 - 5*e6/256) * lat0
            - (3*e2/8 + 3*e4/32 + 45*e6/1024) * SIN(2*lat0)
            + (15*e4/256 + 45*e6/1024) * SIN(4*lat0)
            - (35*e6/3072) * SIN(6*lat0) );
  m  := m0 + (y - FN) / k0;
  mu := m / (a * (1 - e2/4 - 3*e4/64 - 5*e6/256));
  e1 := (1 - SQRT(1 - e2)) / (1 + SQRT(1 - e2));
  p1 := mu + (3*e1/2 - 27*POWER(e1,3)/32) * SIN(2*mu)
           + (21*POWER(e1,2)/16 - 55*POWER(e1,4)/32) * SIN(4*mu)
           + (151*POWER(e1,3)/96) * SIN(6*mu)
           + (1097*POWER(e1,4)/512) * SIN(8*mu);

  s := SIN(p1);  c := COS(p1);  t := TAN(p1);
  C1 := ep2*c*c;  T1 := t*t;
  N1 := a / SQRT(1 - e2*s*s);
  R1 := a * (1 - e2) / POWER(1 - e2*s*s, 1.5);
  D  := (x - FE) / (N1 * k0);

  v_lat := p1 - (N1*t/R1) * ( POWER(D,2)/2
         - (5 + 3*T1 + 10*C1 - 4*C1*C1 - 9*ep2) * POWER(D,4)/24
         + (61 + 90*T1 + 298*C1 + 45*T1*T1 - 252*ep2 - 3*C1*C1) * POWER(D,6)/720 );
  v_lon := lon0 + ( D - (1 + 2*T1 + C1) * POWER(D,3)/6
         + (5 - 2*C1 + 28*T1 - 3*C1*C1 + 8*ep2 + 24*T1*T1) * POWER(D,5)/120 ) / c;

  IF UPPER(p_type) = 'LAT' THEN RETURN ROUND(v_lat * 180 / PI, 7);
  ELSE RETURN ROUND(v_lon * 180 / PI, 7); END IF;
END;
/
```

### 코드 읽기

- 입력이 NULL이면 바로 NULL — UPDATE의 `IS NOT NULL` 조건과 이중 방어.
- `e2`는 이심률 제곱, `ep2`는 제2이심률 제곱.
- `m0`는 원점 위도까지의 자오선 길이, `m`은 대상 점까지 → `mu` → `p1`(발 위도).
- 위도는 D의 2·4·6제곱, 경도는 1·3·5제곱 급수로 보정한다.
- 값 두 개를 한 번에 돌려주려면 객체 타입이 필요해서 `p_type`으로 하나만 반환하도록 단순화했다. 그래서 UPDATE에서 두 번 호출한다.
- **DETERMINISTIC**: 같은 입력이면 같은 결과라고 선언한다. 함수 기반 인덱스에 쓸 수 있고 반복 호출 시 캐싱할 여지가 생긴다.

## 테스트와 일괄 변환

```sql
-- 테스트 : 약 37.2619 / 127.0316
SELECT FN_WCONG_TO_WGS84(507006, 1045259, 'LAT') AS lat,
       FN_WCONG_TO_WGS84(507006, 1045259, 'LNG') AS lng FROM dual;

ALTER TABLE BRANCH ADD (latitude NUMBER(10,7), longitude NUMBER(10,7));
UPDATE BRANCH
   SET latitude  = FN_WCONG_TO_WGS84(x_position, y_position, 'LAT'),
       longitude = FN_WCONG_TO_WGS84(x_position, y_position, 'LNG')
 WHERE x_position IS NOT NULL AND y_position IS NOT NULL;
```

테스트 값을 실제 지점 위치와 지도에서 대조한 뒤에 컬럼을 추가하고 일괄 UPDATE했다. 변환 결과를 컬럼에 저장해 두니 화면은 위경도만 읽으면 됐다.
