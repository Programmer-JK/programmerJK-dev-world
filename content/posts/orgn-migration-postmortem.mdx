[인사·조직 시스템 고도화](/posts/orgn-project)에서 위키에 쌓인 영업점 방문 기록을 Oracle로 옮기는 작업이 가장 크게 무너졌다. 한 번이 아니라 세 번, 매번 다른 층에서였다.

## 무엇을 하려 했나

- 위키에서 추출한 HTML의 본문만 태그 경계로 잘라 임시 테이블에 조각으로 넣는다.
- 첨부 이미지는 base64 data URI로 바꿔 본문에 넣는다.
- 프로시저가 조각을 이어 붙여 기록 한 건의 CLOB으로 적재한다.

## 붕괴 1 — 211장에서 멈춤

**증상**: 이미지 211장째에서 적재가 멈췄다. 오류도 없이 그냥 멈춘 것처럼 보였다.

**원인**: 테이블스페이스가 가득 차서 INSERT가 `statement suspended, wait error to be cleared` 상태로 대기하고 있었다(Resumable 공간 할당). 중간에 끄면 롤백되어 공간이 비고, 다시 돌리면 같은 지점에서 또 멈췄다.

**해결**: 작업 종료 → `TRUNCATE`로 공간 반납 → DBA에 증설 요청, 그리고 이미지 축소. 나눠서 커밋해도 **총량은 같아서** 해결되지 않는다는 점이 핵심이었다.

## 붕괴 2 — 서버 OOM, 1.7GB짜리 한 건

**증상**: 공간을 확보하고 다시 돌리자 WAS가 out of memory로 죽었다. 검토 화면에서 한 건을 열었는데 약 1.7GB였다.

**원인**: 두 가지가 겹쳤다.

- 휴대폰 원본 사진을 그대로 base64로 넣었다. base64는 약 33% 커지고, Java 8 문자열은 글자당 2바이트라 메모리에서는 원본의 약 2.7배가 된다.
- **위키 파일 하나 = 레코드 하나**로 넣었다. 파일 하나에 여러 방문 기록이 묶여 있어 레코드 하나가 73~100MB를 넘었다.

**해결**:

- 긴 변 1280px, JPEG 품질 80%로 축소. 다시 저장하면 사라지는 EXIF 회전 정보는 먼저 픽셀에 반영.
- 기록 제목 단위로 **한 건씩 분리** — 저장 단위를 원천 파일이 아니라 화면에서 조회하는 단위에 맞췄다.

**결과**: 레코드당 약 10MB, 전체 약 5GB → 1/10, 렌더링 10배 이상.

## 붕괴 3 — Oracle DB 서버 다운

**증상**: 적재를 반복하던 중 DB 서버가 내려갔다.

**원인**: 프로시저에서 `DBMS_LOB.CREATETEMPORARY`로 만든 임시 LOB을 `FREETEMPORARY`로 해제하지 않았다. 캐시를 쓰는 임시 LOB이 계속 쌓였다.

**해결**: 사용이 끝나면 명시적으로 해제하고, 예외 경로에서도 `ISTEMPORARY`를 확인해 해제한 뒤 원래 오류를 다시 던지도록 바꿨다. 자세한 내용은 [Oracle 임시 LOB과 공간 부족 진단](/posts/oracle-temporary-lob-space)에 있다.

## 그 밖의 잔해

| 문제 | 원인 | 해결 |
|---|---|---|
| 대체키(AK) 위반 | 모든 건이 같은 소속·사원·방문일 | 건마다 방문 시각을 증가 |
| 방문 ID가 0, "부적합한 열 인덱스" | 프로시저 OUT 파라미터를 바꾸고 Java는 그대로 | `?` 개수와 `registerOutParameter` 번호 맞춤 |
| 진행률 폴링이 안 멈춤 | `setInterval` 미해제 | 응답 후 `setTimeout`으로 다음 한 번만 예약 |
| 운영에서 `NoClassDefFoundError: MigWeb$1` | 익명 클래스 파일이 반영 목록에서 빠짐 | `$` 파일까지 반영 ([배포 교훈](/posts/closed-network-deploy-lessons)) |
| `ExceptionInInitializerError` | static 필드에서 설정값을 읽다 실패 | 초기화를 실행 시점으로 이동 |

## 배운 것

- **층을 하나씩 걷어내야 다음 층이 보인다.** 공간 문제를 풀어야 OOM이 보였고, OOM을 풀어야 LOB 누수가 보였다.
- **임시 LOB은 자동으로 정리되지 않는다.** 생성과 해제를 예외 경로까지 한 쌍으로 관리한다.
- **이미지는 화면에 보일 크기로 저장한다.** 원본 크기가 곧 레코드 크기가 된다.
- **데이터 단위는 조회 단위에 맞춘다.** 크기 문제와 렌더링 문제가 함께 풀렸다.
- **배포 후 기능별 확인 체크가 필요하다.** 10월 27일 운영 배포 뒤 누락 파일로 한 번 더 넘어졌고, 다음 날 운영 마이그레이션을 마쳤다.
