금융권 폐쇄망 프로젝트에서 가장 크게 배운 건 기술이 아니라 환경이었다. **반입 절차**와 **반영 파일 목록 기준 배포**가 기술 선택과 코드 작성 방식까지 바꿨다.

## 들여오는 비용이 기술 선택 기준이 된다

외부 라이브러리, 지도 파일, 라이선스는 모두 반입 절차를 거친다. 요청하고, 기다리고, 들여온 뒤 환경 차이를 다시 검증해야 한다.

- 새 에디터(editor.js)를 반입하는 대신 **이미 들어와 있는 Summernote를 플러그인으로 확장**했다. 사전 테스트로 플러그인 추가에 문제가 없음을 확인하고, 실제 환경 이슈는 반입 후 검증하기로 했다.
- 보안상 쓸 수 없게 된 외부 지도 API는 **반입 가능한 지도 라이브러리로 교체**했다. 개발 → 파일 반입 → 소스 적용 → 라이선스와 추가 파일 반입 → 개발서버 → 운영 순서였다.
- 반입 대기 시간은 일정에 미리 넣는다.

## 소스 1개 ≠ class 파일 1개

| 소스 | 컴파일 결과 |
|---|---|
| 최상위 클래스 | `A.class` |
| 내부 클래스 | `A$Inner.class` |
| 익명 클래스 | `A$1.class` |
| Java 8 람다 | 실행 시 만들어져 **파일이 생기지 않음** |

반영 목록을 소스 기준으로 만들면 `$` 파일이 빠지기 쉽다. 실제로 운영 배포 후 `NoClassDefFoundError: MigWeb$1`이 났다. 익명 `Runnable`이 따로 컴파일된 파일이 목록에서 빠진 것이다.

> 파일 목록으로 반영하는 환경에서 "내부·익명 클래스 금지"는 품질 규칙이 아니라 **배포 실수 방지 규칙**이다. 람다나 별도 최상위 클래스로 쓰면 소스 1개 = class 1개가 된다.

## 클래스를 바꿨는데 그대로다

WAS는 클래스를 처음 쓸 때 한 번 로드해 계속 쓴다. class 파일만 바꿔도 이미 로드된 클래스는 그대로라서 **재배포나 WAS 재시작**이 필요하다.

## 배포 타임라인과 누락

반영 파일 목록을 여러 차례 작성했고, 10월 22일 기준 목록으로 27일 운영 배포를 했다. 배포 직후 일부 미배포 파일 때문에 마이그레이션 오류가 났고, 누락분을 반영해 28일 운영 마이그레이션을 마쳤다.

**목록을 만들어도 누락은 생긴다.** 배포 직후 기능별로 바로 확인하는 체크리스트가 필요하다.

## 개발 환경에서 만난 것들

| 증상 | 원인·해결 |
|---|---|
| 조회 툴에서 멈춘 쿼리 | 툴을 강제 종료해도 DB 세션과 SQL은 남는다. `V$SESSION`에서 SID·SERIAL#을 찾아 `ALTER SYSTEM CANCEL SQL`(18c+) 또는 `KILL SESSION` |
| Eclipse 접근 제한 오류 | `sun.misc.BASE64Encoder` 차단 → `Base64.getEncoder().encodeToString(bytes)` |
| Eclipse 실행 오류 | `-clean`, configuration 캐시 삭제, 재설치. 보안 프로그램의 파일 변조 가능성도 의심 |
| SVN 커밋 실패 (E155004) | 작업 사본 잠금 → Cleanup → Break locks → 관련 프로세스 정리 → 재체크아웃. **SVN lock은 자동 만료가 없다** |
| HTTP 302 | 오류가 아니라 리다이렉트. 세션 만료로 로그인 페이지로 보내는 경우가 흔하다. API라면 401이 적절 |

## 공유 자원은 다른 업무로 번진다

테이블스페이스가 차거나 세션이 멈추면 같은 DB를 쓰는 다른 업무까지 영향을 받는다. 이런 문제에서는 **원인 확인과 원복이 우선**이다. 마이그레이션 중 공간 부족과 DB 서버 다운을 겪으며 체감했다 ([유적 기록](/posts/orgn-migration-postmortem)).

## 정리

- 폐쇄망에서는 들여오는 비용이 기술 선택 기준에 들어간다.
- 배포 방식이 코드 규칙을 만든다 — 파일 목록 반영이면 소스 1개 = class 1개 구조가 안전하다.
- 배포 후에는 기능별로 바로 확인한다.
