첨부파일(BLOB)을 조직명 폴더로 묶어 ZIP 하나로 내려받는 기능이 필요했다. 다른 화면에서도 SQL만 바꿔 쓰고 싶어서 공통 Servlet으로 설계했다.

## 템플릿 메서드 패턴

상위 추상 클래스가 처리 순서를 고정한다.

> 검증 → 조회 → 파일 쓰기 → 압축 → 전송 → 정리

달라지는 부분(SQL, 바인딩, 파일명)만 하위 클래스가 구현한다. 공통 버그를 한 번 고치면 모든 화면에 반영된다.

```java
public abstract class AbstractZipDownloadServlet extends HttpServlet {
  /** 목록 SQL. FOLDER_NM, FILE_ID, FILE_NM 별칭 필수 */
  protected abstract String getListSql();
  protected abstract void bindListParams(PreparedStatement pstmt, HttpServletRequest req)
      throws SQLException;
  protected abstract String getZipFileName(HttpServletRequest req);

  protected String validate(HttpServletRequest req) { return null; }
  /** 구버전 압축프로그램 대응 시 MS949 */
  protected Charset getEntryCharset() { return StandardCharsets.UTF_8; }
  /** 세션 단위 중복 실행 차단 */
  protected boolean useSessionLock() { return true; }
  ...
}
```

- **추상 메서드 3개**는 반드시 구현한다: 목록 SQL, 바인딩, ZIP 이름.
- **훅 메서드 3개**는 기본값이 있고 필요할 때만 재정의한다: 검증(null이면 통과), 엔트리 인코딩, 세션 잠금.
- SQL 결과 별칭 `FOLDER_NM`·`FILE_ID`·`FILE_NM`은 Javadoc에 적은 **계약**이다. 상위 클래스는 이 이름으로만 결과를 읽는다.

## 화면별 구현

```java
@Override
protected void bindListParams(PreparedStatement pstmt, HttpServletRequest req)
    throws SQLException {
  pstmt.setString(1, trim(req.getParameter("targetId")));
  String type = req.getParameter("type");
  if (isNotBlank(type)) pstmt.setString(2, type.trim());
  else                  pstmt.setNull(2, Types.VARCHAR);   // NVL(?, col) → 조건 없음
}

@Override
protected String getZipFileName(HttpServletRequest req) {
  return trim(req.getParameter("targetId")) + "_첨부.zip";
}
```

`setNull(n, Types.VARCHAR)`로 타입을 지정해야 한다. 타입 없는 NULL은 `NVL(?, col)`에서 타입 추론에 실패해 `ORA-00932`가 나고, 숫자 컬럼이면 `ORA-01722`가 난다.

## 파일 다운로드 응답

- `Content-Type: application/zip`
- `Content-Disposition: attachment; filename*=UTF-8''인코딩된이름` — 한글 파일명은 URL 인코딩
- `Content-Length`를 주면 브라우저가 진행률을 보여준다. 완성된 ZIP 크기를 알아야 해서 **임시 파일로 먼저 만든다.**
- 응답이 커밋되면(`isCommitted()`) 상태 코드와 헤더를 바꿀 수 없다. 그 뒤의 `sendError`는 `IllegalStateException`.

## ZIP 엔트리 이름 인코딩

`new ZipOutputStream(out, charset)`(Java 7+)으로 파일명 인코딩을 지정한다. UTF-8은 최신 압축 프로그램에선 정상이지만 오래된 도구에선 한글이 깨질 수 있어서, MS949로 바꿀 수 있는 재정의 지점(`getEntryCharset`)을 뒀다.

## BLOB 읽기와 정리

- `ResultSet.getBinaryStream`으로 스트림 복사한다. 바이트 배열로 한 번에 읽지 않는다.
- try-with-resources로 커넥션·스트림을 닫고, 임시 폴더는 `finally`에서 삭제한다.

## 코드 리뷰와 테스트에서 잡은 것

| 문제 | 수정 |
|---|---|
| 정제 후 파일명이 비어 null, 길이 자르기에서 확장자 유실 | 기본 파일명으로 대체, 확장자를 떼고 본문만 자름 |
| 전송 시작 후 오류 응답 → `IllegalStateException` | 전송 시작 여부와 `isCommitted()` 확인 후에만 오류 응답 |
| Windows 대소문자 파일명 충돌, `mkdirs()` 경쟁 | 대소문자 무시 중복 검사, 생성 후 존재 여부로 판단 |
| 정리 cron이 루트까지 삭제 | `-mindepth 1 -maxdepth 1` |
| 동시 실행 카운터가 음수 | 값 보정 |

## 화면 쪽

숨은 iframe과 숨은 form(`method="post"`, `target`)으로 제출해서 성공·실패 모두 페이지 이동이 없다. 작업 폴더는 `java.io.tmpdir` 기준이고 운영에서는 시스템 프로퍼티로 바꿀 수 있게 했다.

## 정리

재사용할 기능은 **SQL 별칭을 계약으로 고정**하고 공통 흐름을 추상 클래스로 분리한다. 새 화면은 SQL 한 개와 메서드 세 개면 된다.
